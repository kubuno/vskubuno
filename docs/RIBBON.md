# Kubuno Ribbon — a designable ribbon component family — design note

> Scope: product request (2026-09-30) "the existing Kubuno desktop apps must be editable and buildable in
> Visual Studio, their views included"; for the Office editors (Documents first) that means **the ribbon must
> be a full designable component family, like a WinForms/WPF ribbon**: every tab, group, button, gallery,
> QAT item and Backstage entry is a real class of the control hierarchy, listed in the Toolbox (a "Ruban"
> group), selectable on the design surface, with its own properties and events in the Properties window, a
> typed field generated by `#[kubuno_desktop::view]`, instantiable from code and extensible by derivation.
>
> **Status: first increment built (2026-10-01) — see §11 « As built ».** It builds on `XML_VIEWS.md` (format), `EVENTS.md` (control
> hierarchy EVT-7a, custom controls EVT-7b, router), `DESIGNER.md` (design surface, Toolbox, Properties window)
> and `PROGRAMMING-MODEL.md` (`#[kubuno_desktop::view]`, the `kubuno-desktop` facade). The runtime rendering reuses the
> existing port of the web ribbon, `kubuno_desktop_ui::ribbon` (`desktop/windows/src/crates/kubuno-desktop-ui/src/ribbon.rs`),
> which Documents already uses through a Rust declaration (`desktop/windows/src/documents/src/ribbon.rs`).

## 0. Sources studied

The segmentation below was chosen after comparing four existing ribbon models (summarised from their
documentation; the class and attribute names quoted are theirs):

- **WPF Ribbon** — `System.Windows.Controls.Ribbon`:
  <https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.ribbon>
- **Windows Ribbon Framework** (Win32, UICC markup) — schema and size templates:
  <https://learn.microsoft.com/en-us/windows/win32/windowsribbon/windowsribbon-schema>,
  <https://learn.microsoft.com/en-us/windows/win32/windowsribbon/windowsribbon-templates>
- **Office Fluent customUI** (MS-CUSTOMUI):
  <https://learn.microsoft.com/en-us/openspecs/office_standards/ms-customui/31f152d6-2a5d-4b50-a867-9dbc6d01aa43>
- **Community Toolkit TabbedCommandBar**:
  <https://learn.microsoft.com/en-us/dotnet/communitytoolkit/windows/tabbedcommandbar/>
- **Fluent.Ribbon** (open-source WPF ribbon): <https://github.com/fluentribbon/Fluent.Ribbon>

## 1. What exists today, and what is missing

| Piece | State |
|---|---|
| `kubuno_desktop_ui::ribbon::Ribbon` | A data-driven port of the web `Ribbon.tsx`: `RibbonTab` → `RibbonGroup` → `RibbonItem` (kinds Button, Toggle, Dropdown, Split, Menu, Gallery, Separator, Custom), strip quick actions, contextual tabs (per-tab accent only), collapse + peek, responsive folding (the right-most groups fold into a chip, one by one), `Backstage` (sections only; the caller paints the content). Events are string ids (`RibbonEvent::Clicked(id)`…). |
| `kubuno-desktop-views` registry | **No ribbon element.** Closest: `<Toolbar>`/`<ToolbarItem>` (flat, literal attributes only). |
| Structural children in the designer | `ToolbarItem`, `TabItem`… are read by their parent's `build`; they are **not** `DesignSlot`s, so they have no bounds in the `LayoutMap`, cannot be selected on the surface, receive no routed events and cannot be bound (`literal_str`). |
| Command bus | None. `kubuno_desktop_controls::buttons::CommandRef` exists with "Not yet honoured" (`buttons.rs:636-728`). |
| Designer | Collection editor: one child tag, flat (`ChildCollectionPlanner`, `CollectionEditorDialog`). No smart tags / designer verbs yet. |

Model limits of `kubuno_desktop_ui::ribbon` that this design needs lifted: icons are `&'static str` (XML strings are
not), no hit rectangles exposed per item/group, no CheckBox / editable ComboBox / spinner / text box items, no
dialog launcher, no contextual tab *group* header, no sub-menus, one-row galleries without drop-down expansion or
categories, `Custom` items paint only (no measure, no input), no hosted Backstage content, no size levels
between "full" and "folded into a chip", no KeyTips.

## 2. Which ideas we adopt, and why

| Idea (source) | Decision | Why |
|---|---|---|
| Every element is a control with a shared ribbon property service (WPF `RibbonControlService`) | **Adopted**: a `RibbonControl` level (§3) carries the common ribbon properties. | The product requirement is "every element is a control"; one level carrying the common surface is exactly our EVT-7a rule "do not re-implement what a base carries". |
| Commands separated from presentation (Win32 `Application.Commands` + `CommandName`) | **Adopted**, generalised: a non-visual `<Command>` component (§4). | Documents has ~200 commands; the same command appears in the ribbon, the QAT, the context menu, keyboard shortcuts and (later) a mini toolbar, with ONE enabled/checked/label state. It also gives `CommandRef` (kubuno-desktop-controls) a real meaning for every button-like control. |
| Separate `Commands` and `Views` files (Win32) | **Not adopted.** Commands live in the same `.kbview` (tray components), or in a shared `.kbview` user control. | `.kbview` is the single source of truth; a second file would drift. |
| Group size definitions + per-tab scaling policy (Win32 `SizeDefinition`, `ScalingPolicy`; WPF `RibbonGroupSizeDefinition`) | **Adopted** (§5), with a default `Auto` policy that reproduces today's behaviour. | Explicit, designable collapse order, and Medium/Small levels before a group folds into a popup (Office behaviour the web port lacks). |
| `ControlGroup` / `buttonGroup` / `box` | **Adopted** as `RibbonControlGroup` (joined buttons: B I U…) and `RibbonBox` (row/column). | The Police and Paragraphe groups need them to lay out like Word. |
| In-ribbon / drop-down / split-button galleries, categories (Win32, WPF `RibbonGalleryCategory`) | **Adopted**: one `RibbonGallery` with `Display`, plus `RibbonGalleryCategory`. `RibbonFilterMenuButton` deferred. | Styles (in ribbon), colours (in a split menu), tables/margins (drop-down). |
| `DropDownColorPicker` (Win32) | **Adopted** as `RibbonColorPicker` (a split button with a colour gallery + "More colours…"). | Font colour, highlight, shading, page colour: four uses in Documents alone. |
| `FontControl` (Win32) | **Deferred.** Documents uses separate combo boxes + toggles, like the web. | Parity with the web first. |
| Rich screentips (WPF `RibbonToolTip`, customUI `supertip`) | **Adopted as properties** (`ScreenTipTitle`, `ScreenTipText`, `ScreenTipImage`, `ScreenTipFooter`), not a class. | They belong to the command, which feeds every surface. |
| KeyTips (all four) | **Adopted** (`KeyTip` on tabs, groups, controls; auto-assigned when missing; conflicts diagnosed). | Keyboard accessibility; the `mnemonic.rs` Alt infrastructure is reusable. |
| QAT with "Add to Quick Access Toolbar" (WPF `Clone`, `QuickAccessToolBarId`, Fluent.Ribbon) | **Adopted**, customisation persisted per user (a later lot). | Office users expect it. |
| `ApplicationMenu` (Office 2007, WPF) | **Not adopted.** We use the **Backstage** (customUI `backstage`, Fluent.Ribbon), like the web. | The web editors show a Backstage. |
| Backstage columns, groups, task groups (customUI) | **Partly adopted**: `BackstageTab` hosts any view (a user control), which covers columns and groups with ordinary layout. | No need for a second layout vocabulary. |
| Merge by id with `insertAfterMso`/`insertBeforeMso` (customUI) | **Adopted for extensibility** (§8): a `RibbonExtension` fragment or code merges tabs, groups and items into an existing ribbon by `x:Name`. | Modules and plugins (assistant, flow…) can add a group to the Documents ribbon without editing its view. |
| `dynamicMenu` and `get*` callbacks (customUI) | `dynamicMenu` is **adopted** as `OnDropDownOpening` filling the items. `get*` callbacks are **replaced by bindings**. | Bindings are our dynamic-value mechanism. |
| `imageMso` | **Not adopted.** Icons are names of the shared Lucide/themed icon set. | Same icon set as the web. |
| `ApplicationModes` (Win32) | **Not adopted.** `Visible="{Binding …}"` on tabs and groups covers it. | One fewer concept. |
| `ContextPopup` = MiniToolbar + ContextMenu (Win32) | **Deferred.** `ContextMenu`/`MenuItem` gain `Command`; a `MiniToolbar` comes later. | Not in the web editor either. |
| `RibbonWindow` (QAT and contextual headers drawn in the window frame) | **Partly adopted**: `Ribbon.OwnsCaption` already paints the caption in the strip's colours. `QatPosition = InTabStrip \| BelowRibbon \| Caption`. Contextual headers stay in the tab strip. | Matches the web topbar; `Caption` is an option, not the default. |
| Simplified single-row ribbon (TabbedCommandBar, Office "simplified ribbon") | **Adopted as a property** `DisplayMode = Classic \| Simplified`, built in a later lot. Minimise (collapse + peek) already exists; `AutoHide` is deferred. | Useful at small widths; not needed for parity. |
| `HelpButton` (Win32) | **Adopted** as a right-aligned `TabStripItems` slot of the ribbon (help, share, comments). | The web strip has such actions. |

## 3. Class list

The ribbon controls derive from a new level, **`RibbonControl : Control`**. The Properties window hides the
container layout properties `X`, `Y`, `Dock`, `Anchor`, `Margin` and `TabIndex` (`browsable(false)`) and the
validator warns when they are written: the ribbon lays its children out. Bounds come from the ribbon layout (§7.1).

```
Component
├─ Command                         non-visual (component tray): the command state (§4)
└─ Control
   ├─ Ribbon                       the root; Dock="Top" in a Panel
   └─ RibbonControl  [new level]   Label, SmallIcon, LargeIcon, ScreenTip*, KeyTip, Command, CommandParameter,
      │                            ShowLabel, ShowImage, QatId, CanAddToQat, SizeDefinition (per-level size)
      ├─ RibbonTab                 Header, KeyTip, ScalingPolicy            children: RibbonGroup
      ├─ RibbonContextualTabGroup  Header, Color                            children: RibbonTab
      ├─ RibbonGroup               Header, Icon (collapsed chip), SizeDefinition, ShowDialogLauncher,
      │                            OnDialogLauncherClick, DialogLauncherCommand
      │                            children: any RibbonItem, RibbonControlGroup, RibbonBox
      ├─ RibbonControlGroup        joined buttons (B I U)                   children: RibbonItem
      ├─ RibbonBox                 Orientation = Horizontal | Vertical      children: RibbonItem
      ├─ RibbonQuickAccessToolbar  Position                                 children: RibbonItem
      ├─ RibbonBackstage           Header ("Fichier")                       children: BackstageTab, BackstageButton, BackstageSeparator
      │  ├─ BackstageTab           Header, Icon                             one child: any view (user control)
      │  ├─ BackstageButton        OnClick, Command
      │  └─ BackstageSeparator
      └─ RibbonItem  [level]       what can stand in a group, a QAT, a menu
         ├─ RibbonButton           OnClick
         │  ├─ RibbonToggleButton  Checked, OnCheckedChanged
         │  ├─ RibbonRadioButton   GroupName, Checked
         │  ├─ RibbonMenuButton    OnDropDownOpening                        children: menu content
         │  │  └─ RibbonSplitButton  OnClick (main part) + menu
         │  │     └─ RibbonColorPicker SelectedColor, OnSelectedColorChanged
         │  └─ RibbonMenuItem      Checked, OnClick                         children: sub-items (sub-menu)
         │     └─ RibbonSplitMenuItem
         ├─ RibbonCheckBox         Checked
         ├─ RibbonComboBox         IsEditable, Width, Text, SelectedValue, ItemsSource   children: Option
         ├─ RibbonTextBox          Width, Text
         ├─ RibbonNumericField     Minimum, Maximum, Increment, Value, Width
         ├─ RibbonGallery          Display = InRibbon | DropDown | InMenu, Rows, Columns, ItemWidth,
         │                         ItemHeight, SelectedValue, OnItemClick   children: RibbonGalleryCategory | RibbonGalleryItem
         ├─ RibbonGalleryCategory  Header                                   children: RibbonGalleryItem
         ├─ RibbonGalleryItem      Value, Label, Icon, Color, (custom preview by derivation)
         ├─ RibbonLabel            (customUI labelControl)
         └─ RibbonSeparator        Label (optional, WPF)
```

Menu content means `RibbonMenuItem`, `RibbonSplitMenuItem`, `RibbonSeparator`, `RibbonGallery` (`Display="InMenu"`)
and `RibbonCheckBox`.

**Why `RibbonControl : Control` and not `: Component`** (WinForms' `ToolStripItem` is a `Component`): the product
requires "every element is a control", and WPF's ribbon does the same. The cost is the inherited layout
properties; they are hidden and diagnosed rather than removed.

**From code** (the `kubuno_desktop::forms` builders, like `Button::new().text(…)`):

```rust
let paste = RibbonButton::new().label("Coller").large_icon("ClipboardPaste").size(RibbonSize::Large)
    .command(&self.cmd_paste);
let group = RibbonGroup::new().header("Presse-papiers").items([paste.into(), cut.into()]);
self.tab_home.groups().insert(0, group);
self.bold.set_checked(true);       // typed field generated from x:Name="bold"
self.ctx_table.set_visible(true);  // RibbonContextualTabGroup
```

**Extensibility.** `#[derive(Component)] #[kubuno(extends = RibbonButton)]` for a specialised button, or
`extends = RibbonItem` with `get_preferred_size` / `on_paint` / the mouse and key `on_…` overrides for a fully
custom item. This replaces `ItemKind::Custom(Rc<dyn Fn>)`, which could only paint.

## 4. The `Command` component

```xml
<Command x:Name="cmd_bold" Label="Gras" SmallIcon="Bold" Shortcut="Ctrl+B" KeyTip="1"
         ScreenTipTitle="Gras (Ctrl+B)" ScreenTipText="Met le texte sélectionné en gras."
         IsCheckable="true" Checked="{Binding Bold}" Enabled="{Binding CanFormat}"
         OnExecute="bold_execute" OnQueryStatus="bold_query_status"/>
```

- It is a non-visual `Component`, shown in the component tray and generic (not ribbon-only).
- `Command="cmd_bold"` is a reference property (editor `reference:Command`, like `ContextMenu`). It is accepted by
  every `RibbonControl`, and also by `Button`, `IconButton`, `MenuItem` and `ToolbarItem`, which gives
  `CommandRef` in kubuno-desktop-controls its meaning.
- **Resolution order**: an attribute written on the control wins, then the command's value, then the default. So
  `<RibbonButton Command="cmd_paste" Size="Large"/>` takes its label, icons and screentip from the command.
- **One state**: `Enabled`, `Checked`, `Label` and the icons live in the command. Every surface showing it (ribbon,
  QAT copy, context menu, mini toolbar) repaints from it. `self.cmd_bold.set_checked(true)` updates them all.
- **Events**: `Execute` (args: `CommandParameter`, source control) and `QueryStatus` (raised before a surface
  paints or opens, WinForms `Idle`-like; optional, bindings usually suffice). A control's own `OnClick` is
  still raised first; a handler that marks it handled suppresses `Execute`.
- **Shortcut**: the command registers its accelerator with the view (routed before the focused control's keys,
  like WinForms `ProcessCmdKey`). This removes the double consumption of the host key queue by the ribbon and
  the router.
- **Commands are optional.** A control without `Command` is self-contained, which suits small apps.

## 5. Adaptive layout: `SizeDefinition` and `ScalingPolicy`

**Sizes.** Every group has four levels: `Large` (ideal), `Medium`, `Small`, and `Collapsed` (a chip that opens
the whole group in a popup, as today). A group's `SizeDefinition` says how its controls appear at each level.
It takes one of three forms:

- a **template name**, the Win32 vocabulary where it applies: `OneButton`, `TwoButtons`, `ThreeButtons`,
  `ThreeButtons-OneBigAndTwoSmall`, `FourButtons` … `ElevenButtons`, `BigButtonsAndSmallButtonsOrInputs`,
  `InRibbonGalleryAndBigButton`, `InRibbonGalleryAndThreeButtons`, `ButtonGroups`, `ButtonGroupsAndInputs`;
- **`Auto`** (the default): today's algorithm. Small items are stacked in columns of three at most; large buttons,
  drop-downs, galleries and menus take a column each; Medium hides small labels; Small hides all labels but the
  large ones and turns large into small;
- an **explicit definition** (child element), per level. Each control has an `ImageSize` (Large, Small or
  Collapsed, meaning hidden at that level), `IsLabelVisible` and an optional `Width`. `ColumnBreak` and `Row`
  allow manual stacking, and control groups are kept together.

```xml
<RibbonGroup x:Name="grp_font" Header="Police" SizeDefinition="Custom">
  <RibbonGroup.SizeDefinitions>
    <GroupSizeDefinition Size="Large">
      <ControlSize Control="font_family" Width="105"/><ControlSize Control="font_size" Width="54"/>
      <Row/><ControlSize Control="bold" ImageSize="Small" IsLabelVisible="false"/> …
    </GroupSizeDefinition>
    <GroupSizeDefinition Size="Medium"><ControlSize Control="font_family" Width="80"/> …</GroupSizeDefinition>
  </RibbonGroup.SizeDefinitions>
  …
</RibbonGroup>
```

(The `Owner.Property` property-element syntax is new to `.kbview`. Without it, the definition would become a
`<GroupSizeDefinition>` child gated under `RibbonGroup`. It is an open question for the format owners;
§9 lists it.)

**Collapse order.** A tab's `ScalingPolicy` holds the ideal sizes plus an ordered list of steps. When the tab
does not fit at a given width, the steps are applied in order until it fits; a step never makes a group larger.

```xml
<RibbonTab x:Name="tab_home" Header="Accueil">
  <RibbonTab.ScalingPolicy>
    <Scale Group="grp_styles" Size="Medium"/>
    <Scale Group="grp_edit"   Size="Small"/>
    <Scale Group="grp_font"   Size="Medium"/>
    <Scale Group="grp_edit"   Size="Collapsed"/>
    <Scale Group="grp_styles" Size="Collapsed"/>
  </RibbonTab.ScalingPolicy>
  …
</RibbonTab>
```

Without a policy, `Auto` applies: right-most group first, `Large` straight to `Collapsed`. That is exactly what
`kubuno_desktop_ui::ribbon` does today (the folding loop around `ribbon.rs:935`), so migrating Documents keeps
pixel parity until someone writes a policy.

**Diagnostics** (language server and designer): a `Scale` names an unknown group; a group goes back up in size
within a policy; a template does not match the group's item count or kinds; two KeyTips collide within one tab;
a `Command` reference is unknown.

**Display modes.** `DisplayMode="Classic"` is the default. `Simplified` shows one row of the controls marked
`SimplifiedVisible="true"` (default: large buttons and toggles), with an overflow menu. `IsMinimized` is today's
collapse + peek (Ctrl+F1).

**Nesting rules** (gated `ChildrenModel::List`, enforced by `validate.rs`, plus a new "at most one" cardinality):

- `Ribbon` takes `RibbonTab`, `RibbonContextualTabGroup`, `RibbonQuickAccessToolbar` (at most one) and
  `RibbonBackstage` (at most one).
- `RibbonContextualTabGroup` takes `RibbonTab`; `RibbonTab` takes `RibbonGroup`.
- `RibbonGroup` takes the `RibbonItem`s, `RibbonControlGroup` and `RibbonBox`.
- The menu buttons and menu items take the menu content (§3).
- `RibbonGallery` takes `RibbonGalleryCategory` and `RibbonGalleryItem`.
- Every `RibbonControl` attribute can be bound.

## 7. Runtime

### 7.1 Rendering and events

- One `RibbonNode` (a registered component, like `ToolbarNode`) builds a `kubuno_desktop_ui::ribbon::Ribbon` from the
  element tree once per compile. Each frame it copies into the ribbon model, through `item_mut`, the live
  state of each element's control (properties, bindings, command state).
- It then calls `Ribbon::frame` and maps each `RibbonEvent` back to the element's control: the item ids are the
  elements' stable ids. `Clicked` raises `OnClick` then `Command.Execute`, `Changed` raises the value events,
  `TabChanged` raises `OnSelectedTabChanged`.
- **Virtual regions.** `kubuno_desktop_ui::ribbon` exposes the rectangle of each tab header, group, item and menu entry.
  The node reports `(element id, rect, control)` to the `LayoutMap` (designer) and to the router (MouseEnter/Leave,
  tooltips, accessibility, `Sender` identity). This is the one new mechanism in `kubuno-desktop-views`, and it serves
  `Toolbar`, `Tabs` and `Breadcrumb` too.
- A `BackstageTab`'s child view is compiled as an ordinary child node and painted in the Backstage content area.

### 7.2 Changes to `kubuno_desktop_ui::ribbon`

- `Cow<'static, str>` icons; rectangles exposed per item and group.
- The Medium and Small levels, `SizeDefinition` and `ScalingPolicy`.
- `RibbonControlGroup` and `RibbonBox`.
- Check box, editable combo box, numeric field and text box items.
- Dialog launcher; contextual tab group header; sub-menus; multi-row galleries with categories and a drop-down
  expansion; the colour picker.
- A trait-object custom item (measure, paint, input).
- KeyTips (Alt), QAT position and QAT "Add/Remove".
- `Simplified` mode.

The web parity rules of `ribbon.rs` (metrics, colours) stay.

## 8. Extending another app's ribbon

```xml
<!-- assistant.kbview fragment, merged into the Documents ribbon when the assistant module is installed -->
<RibbonExtension Target="ribbon">
  <RibbonTab Merge="tab_review">
    <RibbonGroup x:Name="grp_ai" Header="Assistant" InsertAfter="grp_comments">
      <RibbonButton Label="Résumer" LargeIcon="Sparkles" OnClick="summarise"/>
    </RibbonGroup>
  </RibbonTab>
</RibbonExtension>
```

- `Merge` targets an existing element by `x:Name`, and `InsertBefore`/`InsertAfter` position the new ones
  (customUI's `insertAfterMso`).
- In code: `ribbon.merge(fragment)`, which returns a handle that removes the fragment.
- Module independence holds: the host never names the extension; discovery goes through the extension registry.

## 9. Designer (vskubuno)

**Toolbox.** A "Ruban" tab lists every class of §3 plus `Command`. After a build, the project's own
`extends = RibbonItem` classes appear in "*Project* Composants".

**Selection on the surface.**

- A click on a tab header selects the `RibbonTab` and makes it the design-time active tab (not serialised).
- A click on a group's label or background selects the `RibbonGroup`; a click on a control selects it.
- Contextual tab groups are always shown in design mode, with a dashed outline and "visible at run time when…".
- Clicking « Fichier » shows the Backstage with its tabs and buttons selectable.
- Floating surfaces never open in design mode. Clicking a split or menu button's chevron opens a **design-time
  drop-down** inside the surface where its menu items are selectable (WinForms' ToolStrip "Type here").
- The Document Outline (DSG-8) reaches invisible elements.

**Adding.**

- "+" glyphs at the end of the tab strip (new tab), after the last group (new group), at the end of each group
  (an **"Add ▾"** menu listing the allowed kinds: Button, Toggle, Split, Menu, Check box, Combo box, Gallery,
  Colour picker, Separator, Control group, Box, and the project's items), inside the QAT and inside a
  design-time drop-down.
- Toolbox drops use a horizontal insertion marker inside a group; the gating refuses invalid parents.

**Keyboard and editing.** Arrows move between siblings, Delete removes the subtree, Ctrl+C/V copies the element
XML, F2 edits `Label`/`Header` in place, and dragging reorders across groups and tabs.

**Smart tags (▸)**, which also need the generic smart-tag infrastructure that vskubuno does not have yet:

| Selected element | Verbs |
|---|---|
| Ribbon | Modifier les onglets…, Ajouter un onglet, Ajouter un onglet contextuel, Ajouter la barre d'accès rapide, Ajouter le Backstage, Aperçu à différentes largeurs… |

**Collection editors** (Properties window):

- `Ribbon.Tabs`, `Ribbon.ContextualTabGroups`, `RibbonTab.Groups`, `RibbonGroup.Items`, `…DropDownItems`,
  `RibbonGallery.Items`, `Qat.Items`, `Backstage.Items`. They are **polymorphic** ("Add ▾" lists the allowed
  types) and **nested**: a member's own collection row opens a stacked editor. The whole edit is one undo unit.
- This extends `ChildCollectionPlanner` from one child tag to a set of tags, recursively.
- `RibbonComboBox.Items` keeps the string-list editor.

**Scaling editors.**

- `Stratégie de mise à l'échelle…` is an ordered list of `(group ▾, size ▾)` steps, with up/down buttons and
  diagnostics inline.
- `Taille…` is a template picker (thumbnails of each template filled with the group's actual controls), or a
  per-level grid for a custom definition (control × Large/Medium/Small: ImageSize, label, width, row break).

**Width preview.** A designer toolbar offers a width slider and presets (1920, 1280, 1024, 800, 600 DIP), plus
"play" to sweep from wide to narrow. The surface re-lays out the ribbon at that width and highlights the scaling
step in effect, so the collapse order can be checked without resizing the document window.

**Commands.** The tray shows the `Command`s; selecting one highlights every control that references it.
`Command` properties have a reference drop-down plus « Nouvelle commande… ».
