# Resources — `.kbres` files, the typed `Resources` class, `{Res key}` and the resource editor

The Kubuno equivalent of Windows Forms' `Resources.resx`, its strongly typed `Properties.Resources` class, the
Visual Studio resource editor, per-form resources and satellite assemblies. It also covers foundation lot **F2
"Localisation in views"** of [DESKTOP-MIGRATION.md](DESKTOP-MIGRATION.md) (drive: 49 languages).

Part 1 is the design (what was decided and why). Part 2 is the as-built record: what exists, where, how it was
verified, and what is left.

---

## Part 1 — Design

### 1. What Windows Forms gives, and what we keep

| Windows Forms | Kubuno |
|---|---|
| `Resources.resx` (XML, `<data name>`, base64, `ResXFileRef`) | `resources.kbres` (XML, one element per entry, base64, `File=`) |
| `Resources.fr.resx` → satellite assembly `fr\App.resources.dll` | `resources.fr.kbres` → embedded in the same executable, parsed on first use |
| `Properties.Resources.Logo` (generated by ResXFileCodeGenerator, checked in) | `Resources::logo()` generated at compile time by `kubuno::resources!` (never checked in) |
| `CultureInfo.CurrentUICulture`, fallback `fr-CA` → `fr` → invariant | `kubuno::resources::culture()`, same fallback plus `fr-CA` → `fr-FR` |
| `ComponentResourceManager` + `Localizable=true` (per-form `.resx`) | per-view `main_view.kbres` + `{Res …, Source=main_view}` (see §6) |
| Resource editor (Strings / Images / Icons / Audio / Files / Other) | Kubuno Resource Editor, same categories, plus one column per culture |
| "Select Resource" dialog (local resource / project resource file, Import…) | same dialog, writes a path or `{Res key}` |

### 2. File format: XML, one entry per line

```xml
<?xml version="1.0" encoding="utf-8"?>
<Resources Version="1">
  <String Name="welcome_text" Comment="The home page greeting">Welcome to Kubuno</String>
  <Image Name="logo" File="images/logo.png"/>
  <Icon Name="app" File="app.ico" Comment="16, 32, 48 and 256 px"/>
  <Image Name="dot" Format="png">iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==</Image>
  <Audio Name="ding" File="sounds/ding.wav"/>
  <File Name="license" File="LICENSE.txt" Text="true"/>
  <Color Name="accent" Value="#3366FF"/>
  <Font Name="heading" Value="Segoe UI, 14pt, style=Bold"/>
</Resources>
```

**XML, not TOML**, because:
- the views (`.kbview`) are XML: one syntax in the project, the same escaping rules, and Visual Studio colours both;
- string values are often multi-line and contain quotes, `#`, `=` — XML text content holds them verbatim, where TOML
  needs `'''…'''` blocks whose rules developers get wrong;
- a comment per entry is an attribute, next to the value, not a separate `# comment` line that drifts;
- `.resx`/`.resw` (the import source) are XML too, so one small reader serves both.

**Diff-friendly** by construction: a fixed canonical form (declaration, `<Resources Version="1">`, one entry per line,
two-space indentation, LF, final newline, base64 wrapped at 76 columns). The Rust writer
(`kubuno_resources_model::ResourceFile::to_text`) and the C# writer (`KbresFile.ToText`) produce the same bytes
(both tested on the same sample). Entries keep the developer's order (no sorting).

**Entry kinds**: `String`, `Image` (SVG, PNG, JPEG, BMP, GIF, ICO, TIFF, WebP), `Icon` (usually a multi-size ICO),
`Audio`, `File` (bytes, or UTF-8 text with `Text="true"`), `Color` (`#RRGGBB`, `#AARRGGBB`, `#RGB`, `r, g, b[, a]`),
`Font` (the `.kbview` `Font` syntax). **Linked** (`File="…"`, relative to the `.kbres` file, forward slashes) or
**embedded** (`Format="png"` + base64 content), like `.resx`'s `ResXFileRef` vs. inline data.

**Names**: letters, digits, `_ . - +`, starting with a letter or `_` (dots for per-view entries `okButton.Text` and
imported `.resw` keys; `+` for drive's `Medium++`). The generated accessor is the snake_case form
(`okButton.Text` → `ok_button_text`, `Medium++` → `medium_plus_plus`, keywords get a `_`); two names with the same
accessor are a compile error.

**Several files per project** are allowed: each is a *set* named after its stem (`resources`, `strings`, `errors`,
`main_view`). **Satellites**: `resources.fr.kbres`, `resources.de-DE.kbres` (a culture name is the last dotted part,
`app.icons.kbres` is a set named `app.icons`). A satellite holds only what it translates, same element kinds;
entries the neutral file lacks are warned about (never used), a different kind is an error.

### 3. Culture and fallback

`culture()` follows Windows' display language (`GetUserPreferredUILanguages`) until `set_culture` is called
(`CurrentUICulture`-like). A lookup in `fr-CA` tries `fr-CA`, then `fr` (the .NET order), then — a Kubuno addition for
sets that only ship specific cultures, like drive's `fr-FR` — the other cultures of the same language (`fr-FR`), then
the neutral file. `"invariant"` (or `""`) shows the neutral values.

`set_culture` raises a change notification (`on_culture_changed`); the view layer subscribes once per process and
repaints every window, so a running application switches language **live**.

### 4. Runtime and code generation (`kubuno-resources`, re-exported as `kubuno::resources`)

```rust
kubuno::resources!("resources.kbres");               // pub struct Resources
kubuno::resources!(pub(crate) Strings, "strings.kbres");

let title: &'static str = Resources::welcome_text();  // current culture
let logo = Resources::logo();                          // Image { bytes, format, uri() = "kbres:resources/logo" }
let sizes = Resources::app().sizes();                  // Icon: [(16,16), (32,32), …]
Resources::ding().play();                              // Audio (WAV, PlaySound from memory)
let accent = Resources::accent().to_hex();             // Color
kubuno::resources::set_culture("fr");                  // every {Res …} repaints
```

- The macro reads the neutral file **at compile time** (an invalid file, a missing linked file or an accessor
  collision is a compile error at the path literal), finds the satellites beside it, and embeds everything with
  `include_str!` / `include_bytes!` (absolute paths, so rustc rebuilds when one changes): no loose file at run time.
- Generated code is tiny (one accessor per entry calling the embedded `StaticSet`); the satellites are embedded as
  text and parsed on first use of their culture (Drive's own approach for 49 × 1 450 strings — compile time stays
  flat). Parsed cultures are kept for the process, which is what lets accessors return `&'static str`.
- Every set registers itself for `{Res …}` lookups **before `main`** (a `.CRT$XCU` initializer) and again on first use.
- **rust-analyzer**: the `data_source!` pitfall (no `Span::local_file` in its proc-macro server) is handled the same
  way: the path is resolved relative to the calling file, then `src/`, then the package root, then as the unique file
  under `src` whose path ends with the given one.
- A culture file added later is not tracked by rustc (it only tracks what it embedded): the `.rsproj` build touches a
  neutral file older than one of its satellites before compiling; outside Visual Studio, save the neutral file.

### 5. Views: `{Res key}`

```xml
<Panel Title="{Res app_title}" Icon="{Res app_icon}">
  <Panel BackgroundImage="{Res banner}" BackgroundImageLayout="Stretch"/>
  <Label Text="{Res welcome_text}" ForeColor="{Res accent}" Font="{Res heading}"/>
  <Button Text="{Res save_text, Source=strings}" Icon="{Res save}"/>
</Panel>
```

- `{Res key[, Source=set]}` is parsed like a binding, so **every bindable property** takes one (text, numbers, bools,
  colours, fonts, images). It is one-way, resolved each frame in the current culture: no rebuild on a switch.
- Image properties receive the URI `kbres:<set>/<key>`; `kubuno_controls::styled::load_image` resolves it when painting
  (WIC for raster formats, the icon module's SVG renderer for SVG), cached by content, so a localised picture follows
  the culture. The icon properties (icon agent, `docs/ICONS.md`) go through the same URI.
- **Value syntax agreed with the icons work**: an image/icon value is a path relative to the view
  (`resources/logo.png`), a Kubuno icon name (`Save`), or `{Res key}`.

### 6. Per-view resources and "Localizable"

A view may have its own resource file with the same stem, `main_view.kbres` (+ `main_view.fr.kbres`), nested under it
in Solution Explorer like `Form1.resx`. It is an ordinary set named `main_view`, referenced explicitly:
`Text="{Res okButton.Text, Source=main_view}"`.

**Chosen model** (instead of WinForms' implicit `Localizable=true` property values): every localised value is an
explicit `{Res …}` in the XML. Reasons: the XML stays the single source of truth (nothing hidden in a side file
overrides what the view says), the designer, the language server and the runtime need one mechanism instead of two,
and diffs show which properties are localised. The WinForms gesture "switch Language to French, edit Text" is the
next step on top of it (designer writes the French value into `main_view.fr.kbres` when the edited property is a
`{Res}`); not built yet (§ Part 2, open items).

### 7. Design time

- The designer sends the project's sets to the design surface (`setResources {culture, sets}`) when the surface
  starts, when a `.kbres` or a picture of the project changes on disk, and when the **Langue / Language** picker of the
  Design | XML | Split strip changes. "(Default)" shows the neutral values; the other entries are the project's
  cultures. It is a preview: nothing is written.
- Language server (`kubuno-views-ls`): completion of keys after `{Res ` (value, translations, comment, image path and
  picture in the documentation; images first on image properties), hover, go-to-definition into the `.kbres` entry,
  diagnostics: unknown key (error), image property naming a non-image entry (warning), a string untranslated in one of
  the set's cultures (information).

### 8. Visual Studio

- **Kubuno Resource Editor** (default editor of `.kbres`, "View Code" shows the XML): categories, strings grid with
  one column per culture, thumbnails, Add Resource ▾, drag & drop, rename, delete, persistence, cultures, undo/redo.
- **Item templates**: *Kubuno Resource File* (Fichier de ressources) and *Kubuno Localized Resource File* (Fichier de
  ressources localisé, named `resources.fr.kbres`).
- **Select Resource** dialog for image/icon properties: local resource (path + Import…) or project resource file
  (choose the file, its images and icons with thumbnails, Import… into it, preview, details).
- **Solution Explorer nesting**: `resources.fr.kbres` under `resources.kbres`, `main_view.kbres` under
  `main_view.kbview`.
- **F12** on `Resources::logo()` opens the entry (on `Resources`, the file).

### 9. Migration hook: drive

`kubuno-resources-tool import-locales <locales> <out> --name Strings --neutral en-US` converts drive-localization's
one-folder-per-culture `.resw` files into `Strings.kbres` + 48 `Strings.<culture>.kbres`; `check` reports problems and
missing translations; `import-resx` converts one file. Drive would then use `kubuno::resources!("Strings.kbres")` and
`kubuno::resources::string(key)` where it calls `drive_localization::tr(key)` today, and `set_culture` where it calls
`drive_localization::set_culture`. Not migrated yet (by request).

  Windows display language, French). Screenshots dark and light in `C:\kubuno-build\agent-res\out\`.

### Not verified / open

- **Drag & drop** of a file onto the editor could not be exercised live: real mouse input on the shared desktop
  crossed another agent's Visual Studio window, so it was stopped. The drop handler calls the same tested
  `ResourceSetModel.AddFile` as Add Existing File.
- The icon picker's "Project resources" tab (icon agent) calls `ResourcePicker` by reflection; only the image editor
  path was driven live.
- WinForms-style "edit in French writes `main_view.fr.kbres`" (§6) is not built.
- A Button's `Image` property is written and resolved but the Button family does not paint `Image` (use `Icon`).
- `kubuno-resources-tool` import of non-string `.resx` data (bitmaps) is reported, not converted.
- The window title of a running app follows the culture; a native window caption set once by code does not.
